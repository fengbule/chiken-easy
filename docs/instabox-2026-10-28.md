## 复测与部署

```sh
npm ci
npm run lint
npm run test:files
npm run build
CHIKEN_STORAGE=json npm run smoke
CHIKEN_STORAGE=sqlite npm run smoke
npx playwright-core install --with-deps chromium
npm run test:ui
```

真实浏览器测试使用 `scripts/verify-live-ui.mjs`，通过环境变量 `CHIKEN_TEST_BASE` 和 `CHIKEN_TEST_TOKEN` 传入现有实例；不要将凭据写入命令历史或报告。它创建并删除带唯一 `chiken-test-*` 前缀的临时 SFTP 文件，需要一个已配置 SSH 且 `/workspace` 可写的 Agent。测试截图和结果存入 `.local/ui-live/`。

升级只使用本项目 Compose。先备份数据、现有镜像和配置，再分别构建 control 和 agent（后者基于前者），然后 `up -d`，等待健康和 Agent 重连并复跑 live 测试。初次部署需要配置 `.env` 和 `data/ssh/authorized_keys`：公钥文件属主 root、权限 644，`data/files` 属主 1001；秘密不得提交。

sing-box 配置失败回退和最终恢复已经实际验证。完整应用降级/恢复备份没有在本轮执行，不宣称已验证；跨版本回滚应停服务、恢复成套数据与秘密，并使用匹配的原镜像，不可将运行中的 SQLite 文件单独覆盖。
